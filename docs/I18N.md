# Dashboard 多语言（zh-CN / en）

Dashboard 的界面文案按语言从词典取，服务端只给消息（键加参数），不按语言拼文案。本文是多语言的设计说明和写代码时的约定：新增或迁移页面时照这里做。

## 1. 问题与依据

Dashboard 原来只有中文，而且中文散落在三处，都不能按语言切换：

- **前端组件里写死的文字**：`web/src/app/Shell.tsx` 的导航、菜单，`pages/login.tsx`、`pages/error.tsx` 的标题和说明，`components/CopyButton.tsx` 的"已复制"等。
- **服务端拼好的整句中文**：错误页（`internal/server/web/errors.go` 的 `Heading`、`Reason`、`Links[].Label`）、登录页说明和表单错误（`session.go`）、页面标题（`uiPage.Title`）、操作后的提示（`flashBack` 把整句中文放进 `?flash=`）。前端只能原样显示。
- **非 React 模块里的中文**：`lib/api.ts` 的网络和解析错误、`app/router.tsx` 的跳转失败说明，存在状态里的是译好的字符串，切换语言后不会变；`lib/format.ts` 的相对时间、耗时、状态名称只有中文。

另外 `?flash=` 是任意文字：任何人都能构造带任意提示的链接。

## 2. 范围与取舍

基础设施和契约（Issue #2）用登录页、错误页、外壳、OAuth 失败、一条成功提示（绑定 / 解除绑定 GitHub 账号）和一条表单校验失败（admin token 登录）跑通双语。业务页面按功能域纵切迁移（前端、服务端的页面数据、操作提示、表单校验一起），还没有迁移的域照常显示中文：

| 功能域 | 状态 | 范围 |
|---|---|---|
| 总览与 CI 运行（Issue #3） | 已迁移 | 总览、运行列表、启动构建、run 详情（job 图、重跑对话框、活动）、job 详情（日志面板、产物、发布结果、尝试、job spec）及共用的 `RunRow`、`RunHeader`、`RunSidebar`；取消、重跑、启动构建、产物下载的提示；启动构建的表单校验；日志接口的错误（见 4.2） |
| CI Runner 与 AI 执行节点（Issue #4） | 已迁移 | CI Runner 列表、详情（按台升级、升级记录）、注册新的 Runner、本地缓存（清单、预览、清理），AI 执行节点列表和详情，及共用的 `RunnerSchema`、`RunnerStatus`、AI 执行节点页面上的 Orca 进度行（`pages/ai/orca.tsx`）；暂停、恢复、吊销、删除、升级、取消升级、检查更新、发起清理的提示；注册令牌表单的校验；升级被拒绝和清理预览的说明（见 4.3） |
| AI 审计与开发（Issue #5） | 已迁移 | AI 请求列表和详情、AI 任务详情（attempt、日志、审计报告、开发报告）、AI 开发（工作项列表、任务池、仓库占用、暂停的仓库）、工作项详情（概要、Issue、选题和交付报告、评论意图、attempt 分支），及共用的设计依据（`pages/ai/DesignBasis.tsx`：冻结的元数据、正文对话框、关联任务与依据）；取消、重跑、同步任务池、暂停、恢复、终止、重试的提示；设计依据记录不一致、快照完整性问题和依据关系的说明（见 4.3） |
| 合并队列、设置 | 未迁移 | 后续 Issue（#6–#7） |

| 取舍 | 选择 | 理由 |
|---|---|---|
| i18n 库 | 自己写一层薄的翻译函数（`web/src/i18n/`），用浏览器的 `Intl.PluralRules`、`Intl.NumberFormat`、`Intl.DateTimeFormat` | 需要的只有键查找、参数代入、复数和受限的富文本；成熟库（i18next、FormatJS）带 ICU 解析器和运行时配置，体积和概念都多于需求，而且要额外做"服务端消息"和"富文本不注入"的约束。自己写的部分约 200 行，全部有单元测试 |
| 词典格式 | JSON（`web/src/i18n/locales/zh-CN.json`、`en.json`） | 前端打包进 `kiln-server`（离线可用），Go 的契约测试也能直接读，同一份文案只定义一次 |
| 键和参数的检查 | 键在编译期检查（`MsgKey = keyof typeof zh`，两种语言缺键都是编译错误）；参数名和格式在测试期检查（`messages.test.ts`、Go 的 `text_test.go`） | JSON 导入后值的类型是 `string`，编译期拿不到占位符；测试覆盖两种语言的每一条文案和服务端登记的每一条消息 |
| 服务端文字 | `uiText`：消息编码为 `{"id", "params"}`，原样的文字编码为 JSON 字符串 | 字符串仍然是合法的页面数据：还没有迁移的页面、旧的前端和 fixtures 都不用改；迁移按域进行，不需要一次改完 |
| `?flash=` | 消息形式（JSON）只接受登记为 flash 的消息和合格的参数；其他文字视为还没有迁移的旧提示，截断后原样显示 | 旧提示在所有操作迁移之前还会产生（`flashBack`），直接拒绝会让未迁移的操作没有提示；迁移完成后（Issue #8）可以只接受消息形式 |
| 时间、数量 | 服务端传原始值（Unix 秒、整数），前端按语言和浏览器时区格式化 | 不同用户看到各自的语言和时区；服务端不知道浏览器的时区 |
| 状态、标题、失败说明 | 状态里存消息（`Text`），显示时翻译 | 切换语言后已经显示的提示、失败说明、标题立即更新 |

不做的：Go 侧的翻译引擎（服务端不按语言渲染任何文字）；前端没构建时的占位页（`ui.go` 的 `indexPlaceholder`）同时写中文和英文，不依赖词典；日志正文、AI 报告、仓库名、提交说明等原始内容不翻译。

## 3. 前端

```
web/src/i18n/
  locales/zh-CN.json, en.json   词典
  locale-id.ts                  语言标识、浏览器语言匹配
  datetime.ts                   日期时间格式（Intl.DateTimeFormat）
  messages.ts                   Text 类型、parseText、translate、segments（纯函数，非 React 模块也能用）
  locale.tsx                    LocaleProvider、useLocale、useT、useText、<Msg>、<Trans>
```

### 3.1 当前语言

- 优先级：用户手动选择（`localStorage` 的 `kiln.locale`）> 浏览器的语言偏好（`navigator.languages`，`zh-*` → `zh-CN`，`en-*` → `en`）> `zh-CN`。浏览器存储不可用（隐私模式、被禁用）时读写都按失败处理，选择只在内存中生效。
- 选择保存在浏览器中，刷新、GitHub OAuth 往返、退出登录后保持。
- `LocaleProvider` 在 `RouterProvider` 之上（`app/App.tsx`）：切换语言只重新渲染，页面组件的 key（`view.seq`）不变，不重新挂载，表单输入、打开的对话框、滚动位置都保留。`<html lang>` 和 `document.title` 随语言更新。
- 切换入口：已登录时在头像菜单的"语言"一组；未登录的页面（登录页、错误页）右上角有语言按钮。语言名称总是用该语言自己的写法（"简体中文"、"English"）。
- 没有 `LocaleProvider` 时（单独渲染组件的测试）是 `zh-CN`。不新增模块级的"当前语言"或可变的 translator：需要文字的函数都显式接收语言（`format.ts` 的 `ago(t, now, locale)` 等，不传时为 `zh-CN`，供还没有迁移的页面使用）。

### 3.2 文案写法

- 键用点分（`login.title`、`error.serverHeading`），按页面或组件分组；按状态值拼键的（`runState.queued`）用 `isMsgKey` 检查，词典中没有时原样显示状态值。
- 参数：`{name}` 原样插入；`{name, number}` 按语言格式化数字；`{name, time}` 是 Unix 秒，按语言和浏览器时区格式化；`{name, duration}` 是时长（秒），整分钟写成分钟（"2 分钟"、"2 minutes"），其余写成秒（`span.minutes`、`span.seconds`，`formatSpan`）。服务端的时长（离线判定、租约、一轮领取的最长时间）都按秒传。
- 复数：值写成 `{"one": "…", "other": "…"}`（类别见 `Intl.PluralRules`），按参数 `count` 选择；中文一般只需要普通字符串。
- 富文本：`<code>…</code>`、`<link>…</link>`、`<strong>…</strong>` 等成对标签，渲染时由 `<Trans tags={{ code: (c) => <code>{c}</code> }} />` 提供元素；没有提供的标签按普通文字显示。参数在切分标签之后才代入，参数中的 `<`、`>` 永远是普通文字，不会被当作标签或 HTML。
- 中文沿用原来的写法：Actions 术语保留英文，中文与英文、数字之间留空格。

### 3.3 用法

```tsx
const t = useT()                       // 前端自己的消息：t('nav.runs')、t('shell.userMenu', { login, role })
<Trans id="shell.expired" tags={{ link: (c) => <Link href={url}>{c}</Link> }} />
const text = useText()                 // 服务端给的 Text（属性、标题等纯文本处）
<Msg text={data.Reason} />            // 服务端给的 Text（正文处）
```

页面数据中服务端给的文字用 `textSchema`（`lib/envelope.ts`）解析：字符串原样，`{id, params}` 是消息；格式不对的消息转换为兜底说明，不让整页校验失败。表单错误（`fieldError`）返回 `Text`，用 `<Msg>` 显示。

### 3.4 兜底

| 情形 | 显示 |
|---|---|
| 不认识的消息键（前后端版本不一致） | `message.unknown`："这条提示无法显示（键）：前端与 kiln-server 的版本可能不一致，刷新页面重试。" |
| 消息格式不对（不是字符串也不是 `{id}`、id 不合格） | `message.invalid` |
| 缺少参数、参数类型不对、参数不合格（对象、过长、`NaN`） | 对应位置显示 `…`，其余照常 |
| 引导期的网络错误、非 JSON 响应、页面数据解析失败 | 对应的 `api.*` 消息（`lib/api.ts`），显示在页面顶部，不白屏 |
| 页面数据不符合页面的 schema | `page.dataInvalid` 说明（`app/definePage.tsx`） |

## 4. 服务端（`internal/server/web/text.go`）

- `uiText` 是页面数据中的一段文字：`message(id, strArg(...), intArg(...))` 或 `rawText(s)`。`uiPage.Title`、`uiPage.Flash`、`errorPage` 的标题、原因、入口文字、`loginPage.Notice`、`formState.Errors` 都是 `uiText`。
- 所有消息登记在 `messages`（`msgID` → 参数名和类型、能否放进 `?flash=`）。契约测试（`text_test.go`）检查：
  - 每条登记的消息在 `zh-CN.json`、`en.json` 中都有，参数名与登记的完全相同，按 `number` / `time` 格式化的参数登记为整数；
  - 包中声明的每个 `msgID` 常量都登记了。
- 原样的文字（对象名、`admin.Service` 给出的 NotFound 说明、仓库名等）用 `rawText`，或作为消息的参数，不当作消息键。
- 渲染入口不变：前端请求（`X-Kiln-UI: 1`）返回 JSON，浏览器直接打开返回内嵌页面数据的 `index.html`（`renderPage`）。`render` / `renderStatus` 仍接受字符串标题（原样显示），迁移后的页面用 `renderPage` 传消息。
- 内部错误的规则不变：数据库、网络等内部错误只写日志，页面上是通用的消息加错误编号（`ref`）；未知错误不回显原文。表单和页面数据中的操作失败用 `failureText`（内部错误是 `action.internalError` 加错误编号，其余是 `admin.Service` 给的原样说明），跳转后的提示用 `failureFlash`（每个操作一对消息：`…Failed` 带原样的说明，`…FailedRef` 带错误编号）。

### 4.1 跳转后的提示（`?flash=`）

- 迁移后的操作用 `flashMsg(w, r, to, message(...))`：值是消息的 JSON，只能是登记为 `flash` 的消息。不合格时（编程错误）记录错误，照常跳转、不带提示。
- 服务端渲染页面时用 `parseFlash` 校验地址中的值：
  - 以 `{` 开头的按消息解析：消息必须登记为 flash，参数名与登记的完全相同，文字参数不超过 200 个字符、不含控制字符，整数参数是整数，整个值不超过 1024 字节，JSON 后面不能有多余内容；任一条不满足就不显示；
  - 其他是还没有迁移的旧提示（`flashBack`）：原样显示，超过 600 字节截断。
- 不把 secret、内部错误或富文本放进地址：flash 的参数只是纯文字，前端不把它当作标签。`flashMsg` 先经 `fitFlash` 整理文字参数（对象名、路径、失败说明等原样的文字）：每个参数经 `flashArgText` 把控制字符换成空格、超过 200 个字符截断；整条消息的 JSON 仍超过 1024 字节时（转义后的 `&`、`<` 各占 6 个字节，多字节字符和多个参数也会叠加），再按字节预算截断文字参数并以省略号结尾，预算在文字参数之间平分、短参数用不完的份额留给长参数。整条提示不会因为参数过长而不显示。
- 前端的处理不变：提示只显示一次，之后从地址栏去掉 `flash` 参数，保留其他参数和 `#hash`；表单提交（POST）的结果不重放。

### 4.2 页面脚本调用的接口（日志片段）

- 正常响应不变：正文是日志的原始字节（`text/plain`，不翻译），`X-Next-Offset`、`X-Finished`、`X-Job-State`、`X-Job-Terminal`、`X-Attempt`、`X-Current-Attempt` 是日志的元数据。
- 错误响应（`apiError`）的正文是消息的 JSON（`application/json`），状态码不变：未登录 401（`api.unauthorized`）；参数无效 400（`log.errBadAttempt`、`log.errBadOffset`）；找不到 404（`logError`：按请求的参数说明找不到的是对象本身还是指定的 attempt，job 和 AI 任务各一组消息，不解析 `admin.Service` 的说明）；内部错误 500（`log.errServer`，只带错误编号）。
- 前端（`pages/job/poller.ts`）把 JSON 的错误按消息保存（不是 JSON 时原样显示），断线、服务器出错的重试原因也存消息；`LogViewer` 显示时翻译。搜索结果存位置和数量，不存翻译好的文字。切换语言只重新渲染：已读到的日志、搜索词、阅读位置都保留，不重新读取。

### 4.3 领域层的原因码

领域层不接收语言，给出稳定的原因码和原始参数，由 `internal/server/web` 映射为消息；原来的中文说明（`Error()`、`String()`）保留给 CLI 和日志：

- 手动触发：`planner.DispatchError` 的 `Code`（`ref_not_found`、`workflow_missing`、`not_dispatchable`）和 `Subject`（找不到的 ref 或 workflow 文件名），映射见 `dispatchErrorText`；inputs 的问题是 `workflow.DispatchInputProblems` 返回的 `InputProblem`（`Code`、`Name`、`Options`），映射见 `inputProblemText`。启动构建页的 inputs 字段上是汇总（`runNew.errInputs`），各个问题在页面数据的 `InputProblems` 中，每行一条。
- Runner 按台升级：`upgradectl.Reason`（`Code` 加 `Current`、`Latest`、`Version`、`Expected`、`Detail`）是不能升级或拒绝升级操作的原因，`Blocker` 和 `*RefusedError` 都带它，`RunnerInfos` 同时给出 Admin API 的中文说明（`reason`，CLI 用）和原因码；映射见 `upgradeReasonText`（`runner_text.go`）。原因消息也登记为 flash：升级、取消、检查被拒绝时直接作为提示。不认识的原因码显示 `upgradeReason.unknown`（带原因码）。
- 本地缓存的清理预览：`admin.Service.PreviewRunnerCachePurge` 返回 `admin.CacheNote`（`Code` 加 Runner 名称、清单的生成时间（Unix 秒）、正在执行的 job 数），`PurgeRunnerCache`（CLI）仍给中文的 `notes`，两者来自同一个判断；映射见 `cacheNoteText`。仓库不在 Kiln 中时预览失败的原因是 `runnerCache.errRepoNotFound`（按 `store.ErrRepoNotFound` 判断）。
- 设计依据（外部文档）：记录不一致是 `ai.DocsIssue`（`Code` 加 AI 任务、请求、工作项、快照集的编号；`Unwrap` 为 `ErrDocsBasisConflict`，`Error()` 是原来的中文说明），`RequestDocsView`、`TaskDocsView` 的 `Issue` 带它，`Error` 仍是中文说明；冻结快照的完整性问题是 `docsync.IntegrityIssue`（`Code` 加记录的篇数、实际行数、文档 ID），`SnapshotView.Integrity` 带它；关联任务的依据关系说明是 `ai.RelationNote`（`RelatedTask.NoteCode`，`Note` 仍是中文），依据无法解析的具体原因在 `Issue` / `Detail`。映射见 `ai_text.go` 的 `docsIssueText`、`integrityText`、`relationNoteText`；不认识的原因码、没有原因码的错误（例如任务的 spec 无法解析）原样显示领域层的中文说明。正文接口（`/docs/content`）的错误仍是 `{"code", "message"}`：前端只保存错误码、服务端的说明、是否需要重新登录和 HTTP 状态，显示时按当前语言翻译认识的错误码，不认识或没有错误码时才显示 `message`，切换语言时打开的正文对话框立即更新，不关闭、不重新读取。
- AI 开发的仓库占用：页面数据是结构化的占用者、阶段、状态和原样的原因（`aiDevOccupancy`），由前端按语言组合，不使用 `aidev.Occupancy.Why()` 的中文整句（CLI 仍用它）。工作项操作中已知的失败（工作项不存在、仓库不存在、不能重试、已经结束）各有自己的提示消息（`aiDevFailure`），其余按 `failureFlash`。
- 页面只按语义字段显示状态，不用译文判断：Runner 的连接状态由 `Revoked`、`Online` 决定（`connLabel`），类型由 `Kind`、`Role` 决定（`runnerKindLabel`），注册令牌是否过期由剩余时间决定（`tokenLeft` 的 `expired`），缓存类别、升级进度、升级请求的状态、AI 执行节点的本机状态和 Orca 的进度阶段按状态值查词典（不认识的原样显示）。
- 原样显示、不翻译的：AI 报告（审计报告、选题和交付报告、计划）、外部文档的标题、文档集名称和正文、Issue 和 PR 的标题、AI 任务和工作项记下的原因、请求的配置错误和警告、评论意图的错误、Orca 上报的进度文字；调度器和执行记下的原因（job 的 `Reason`、`WaitReason`，attempt 的 `Message`），发布的错误，合并队列的状态和原因（Issue #6 结构化），`admin.Service` 的校验和前提说明（作为消息的参数或原样文字，Issue #7 结构化），Runner 和 AI 执行节点上报的文字（升级失败的原因、查询最新版本的错误、清理失败的错误、Orca / Docker / 工具链 / Agent 不可用的原因、任务的进度说明），升级请求记录的结束原因。这些是持久化或上报的原文，按原因码结构化需要改各自的写入方，不在页面层按中文匹配反推。

## 6. 迁移一个页面

1. 前端：页面中的文字改为 `t(...)` / `<Trans>`，在两种语言的词典中加文案；`aria-label`、`title`、`placeholder`、表格的 `data-label`、确认对话框都要改。时间、状态名称传 `locale`（`useLocale()`）。
2. 服务端：页面数据中给用户看的文字改为 `uiText`；新增的消息在 `messages` 中登记；操作后的提示改用 `flashMsg`，消息登记为 `flash`。领域层（`admin`、`mergequeue` 等）不接收语言：给出稳定的原因码和原始参数，由 `internal/server/web` 映射为消息。
3. 更新 `web/dev/fixtures` 和测试：检查英文的显示、切换语言后状态不丢。
4. 不要用翻译后的文字做判断（样式、分支）：用状态值或服务端给的语义字段。
